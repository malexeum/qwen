# Fractal Identity Engine — Product Brief v0.2.1 (Full)

## 0. TL;DR

Веб + мобильное приложение, которое превращает звук (микрофон или MP3/WAV) в уникальный фрактальный визуал: постер и GIF-превью.

Пользователь: загрузил звук → уточнил музыкальный стиль → уточнил визуальный стиль → покрутил до 5 слайдеров → пуск → превью с watermark → сохранить / экспортировать hi-res / поделиться.

Ключевое архитектурное изменение v0.2.1: между аудиоанализом и рендером фрактала появляется **перцептивный латентный слой**, делающий связь звук→визуал объяснимой, а не произвольным мэппингом чисел.

---

## 1. Цель продукта

Дать любому пользователю возможность за пару минут получить красивый, уникальный и объяснимый фрактальный постер + GIF-превью для своего звука.

> Одна фраза для команды: **загрузи звук → получи уникальный визуальный идентитет, вычисленный из музыки, а не наклеенный сверху.**

Позиционирование: **«игрушка для всех»** с парой бесплатных генераций и платным hi-res. Потом — усложнение до pro-версии для студий и музыкантов.

---

## 3. Проблема, которую решает продукт

Люди, у которых есть звук — трек, голос, live-выступление — не имеют доступного инструмента, который генерирует визуальный идентитет **из самой музыки**, а не поверх неё. Существующие решения — либо ручной дизайн (дорого), либо случайные AI-картинки (не связаны со звуком), либо десктопные визуализаторы для науки/энтузиастов без продуктовой упаковки.

## 4. Пользовательский сценарий (финальный флоу MVP)

1. **Первый экран**
   - Кнопка «Загрузить звук».
   - Источник: `Микрофон (live)` или `Файл (MP3/WAV)`.

2. **Шаг 1 — Стиль аудио**
   - Сервер считает `AudioAnalysis` (BPM, тональность, энергия, спектр, длительность, повторяемость).
   - Пользователь подтверждает автоподобранный музыкальный стиль или выбирает вручную.

3. **Шаг 2 — Визуальный стиль**
   - Пользователь выбирает mood: Mono Noir, Art/Graphica, Futuristic, Nature, и т.п.
   - Влияет на палитру, линии, фактуру.

4. **Шаг 3 — Параметры (до 5 слайдеров)**
   - Complexity, Symmetry, Density, Noise, Motion.
   - Сохраняются как `UserPreset`.

5. **Шаг 4 — Пуск**
   - Браузер (WebGL/WebGPU) рендерит фрактал по `RenderParams`.

6. **Шаг 5 — Превью и действия**
   - PNG/JPG + GIF-превью с watermark.
   - Кнопки: `Сохранить проект`, `Экспортировать hi-res` (платно), `Поделиться`.

### 5.2. Стало (v0.2.1)
AudioAnalysis → PerceptualLatent → InterpretationProfile + StyleProfile + UserPreset → RenderParams → PosterRenderer

text


### 5.3. PerceptualLatent — новая сущность

Компактное представление трека в человеко-понятных осях:

- `energy` — общая энергия и вариативность.
- `tension` — воспринимаемое напряжение vs разрешение.
- `density` — плотность событий/ритма.
- `brightness` — воспринимаемая яркость спектра.
- `stability` — тональная/формальная устойчивость.
- `smoothness` — гладкость vs резкость переходов.
- `repetition` — степень повторяемости мотивов/секций.
- `section_complexity` — грубая мера структурного богатства.
- `macro_shape_hint` — форма композиции (A–B–A и т.п.).

Реализация: отдельная таблица, привязанная к `AudioAnalysis`/`Track`, либо embedded JSON-блок. Контракт должен быть явным и сериализуемым.

### 5.4. Расширение AudioAnalysis

- `sections` — сегменты с временными границами (интро, куплет, припев, бридж, аутро).
- `section_labels` / `section_ids`.
- `recurrence_groups` — повторяющиеся секции.
- `events` — брейки, кульминации, смены тональности.

Для v0.2.1 достаточно простых, устойчивых эвристик — не требуется точная музыковедческая сегментация.

### 5.5. InterpretationProfile

Декларативный конфиг: как «читать» перцептивные оси в визуальные решения.

Примеры: `organic_fluid`, `geometric_rhythmic`, `dark_tense`, `minimal_stable`, `exploratory_chaotic`.

Каждый профиль определяет: какие оси акцентируются; как оси мапятся на параметры фрактала (symmetry bias, глубина рекурсии, стохастический член, палитра, плотность, скорость эволюции).

Реализация: YAML/JSON конфиги рядом со `StyleProfile`.

### 5.6. Обновлённый style engine

1. **Perceptual resolver**: `AudioAnalysis` → `PerceptualLatent`.
2. **Visual resolver**: `PerceptualLatent` + `StyleProfile` + `InterpretationProfile` + `UserPreset` → `RenderParams`.

### 5.7. Цепочка объяснимости
audio → AudioAnalysis → PerceptualLatent → InterpretationProfile + StyleProfile → RenderParams → Poster

text


Метаданные для будущего pro-режима: какие оси были ключевыми, какой профиль применён, какие события повлияли на композицию.

## 7. Входные/выходные данные

**Вход:**
- Микрофон (live) — Web Audio API, локальный анализ для реактивности.
- Файлы — MP3, WAV, до ~50 МБ.

**Признаки, которые считаем (сервер, Python):**
- BPM, key/mode, energy, spectral centroid/brightness, rhythm density, dynamic range, duration, repetition/structure.

**Выход:**
- PNG / JPG — постер (стандартный и hi-res).
- GIF — короткое зацикленное превью (2–5 сек), основанное на изменении параметров фрактала синхронно с музыкальной структурой.

**Хранение:** до 5 проектов на пользователя (MVP), каждый — трек + `AudioAnalysis` + `PerceptualLatent` + presets + ассеты.

## 8. Технологический стек: Python + Browser

### 8.1. Сервер (Python)
- Анализ аудио: librosa/pyAudioAnalysis/кастомные скрипты — остаются как есть, оборачиваются REST API.
- Вычисление `PerceptualLatent` — rule-based слой над `AudioAnalysis`.
- Определение длительности: pydub/mutagen/ffmpeg.

### 8.2. Клиент (Browser/Mobile)
- Web Audio API — захват микрофона, локальный live-анализ.
- WebGL/WebGPU — шейдеры фракталов (Mandelbrot, Julia, IFS), рендер по `RenderParams`.
- Canvas → экспорт PNG/JPG, offscreen-рендер для GIF.
- Mobile — WebView-оболочка + нативный доступ к микрофону.

### 8.3. Когда переходить на CUDA/GPU-серверы
Не раньше, чем появится: high-res рендер для печати, полноценное видео (MP4/WebM) или сложные 3D-фракталы. Признаки готовности перехода: средний рендер > 5–10 сек, непропорциональный рост CPU-нагрузки на хостере, жалобы пользователей на задержки экспорта.

## 12. Scope v0.2.1

**In-scope:**
- `PerceptualLatent` с базовыми осями (energy, tension, density, brightness, stability, repetition, macro_shape_hint).
- Rule-based mapping `AudioAnalysis → PerceptualLatent`.
- 2–3 `InterpretationProfile` конфига.
- Обновление `resolve-style` для использования нового слоя.
- Видимая реакция рендера на разные интерпретационные профили.

**Out-of-scope (v0.2.1):**
- Полная музыковедческая сегментация.
- Loop-видео (MP4/WebM).
- Pro-режим.
- Multi-user/collaborative.
- AI-heavy генерация (diffusion, LLM-guided visuals).
- Новые входные модальности кроме аудио.

## 13. Риски и митигация

| Риск | Митигация |
|---|---|
| Scope creep — перцептивный слой превращается в «научный отчёт» | Ограничить rule-based маппингом и малым числом профилей |
| Оверфиттинг под конкретные жанры | Обобщённые оси и профили, тест на разных жанрах |
| Рост сложности / падение производительности | Легковесные вычисления, переиспользование уже посчитанных фич |

---

## 14. Критерии приёмки v0.2.1

- `PerceptualLatent` вычисляется и сохраняется для проанализированных треков.
- `InterpretationProfile` конфиги реализованы и используются.
- `resolve-style` даёт разные `RenderParams` в зависимости от профиля.
- Постер визуально различается между профилями, оставаясь привязанным к аудио.
- Основной MVP-флоу пользователя не нарушен.

---

## 15. Дорожная карта за пределами v0.2.1

- **Текст/стихи как вход** — визуализация семантики текста через тот же перцептивный слой (зафиксировано, не забыто).
- **Психологическое тестирование / нелинейные преобразования** — использование движка как универсального «переводчика» сигнала (голос, поведение, физиология) в визуал, включая предсказание исходов.
- **Loop-видео и pro-режим** — следующие итерации после стабилизации перцептивного слоя.
- **Explainability UI** — показ пользователю (сначала в pro-режиме), какие оси и события повлияли на визуал.
- Multi-user/collaborative и AI-heavy генерация — только после устойчивого MVP.
