# Qwen Benchmark Pipeline

Минимальный, но рабочий пайплайн для запуска и анализа бенчмарков моделей семейства Qwen и других LLM.

## Структура репозитория

### Основной раннер

- `benchmark-runner_v4_2.py`  
  Актуальная версия основного скрипта запуска бенчмарков (v4.2).  
  Отвечает за:
  - чтение конфигураций и реестров задач;
  - запуск моделей и сбор результатов;
  - логирование метрик в стандартизированном формате;
  - экспорт сырых логов для последующей генерации отчётов.[cite:2]

- `run_protocol.py`  
  Обёртка над основным раннером, которая:
  - читает `experiment_protocol.yaml`;
  - последовательно запускает сценарии бенчмарков;
  - обеспечивает воспроизводимость экспериментов через единый протокол.[cite:2]

### Конфигурационные файлы (YAML)

- `experiment_protocol.yaml`  
  Описание набора экспериментов:
  - какие модели;
  - какие задачи;
  - какие режимы запуска (контекст, параметры).[cite:2]

- `feature_schema_v2.yaml`  
  Схема признаков/метрик:
  - какие фичи логируются;
  - формат хранения;
  - типы и диапазоны значений.[cite:2]

- `identity_schema_v2.yaml`  
  Схема идентичности модели и запуска:
  - название и версия модели;
  - параметры запуска;
  - идентификаторы экспериментов.[cite:2]

- `input_registry.yaml`  
  Реестр входных задач и датасетов:
  - имя задачи;
  - тип бенчмарка (код, reasoning, QA и т.п.);
  - путь к данным и настройки загрузки.[cite:2]

- `output_taxonomy.yaml`  
  Таксономия выходных метрик и отчётов:
  - базовые метрики;
  - группировка результатов;
  - целевые форматы отчётов (таблицы, агрегаты).[cite:2]

### Генераторы

В репозитории находятся четыре генератора (отдельные Python-скрипты), которые готовят данные и структуры для запуска и анализа.  
Именование и функции зависят от текущей реализации, но рекомендуемый смысл:

- `observe.py`  
  Работает с `input_registry.yaml`:  
  - генерирует/валидирует входные задачи и промпты;  
  - готовит структуры для использования в раннере.

- `generators.py`  
  Работает с `feature_schema_v2.yaml`:  
  - создаёт структуры логирования;  
  - проверяет совместимость фич с текущим пайплайном.

- `metrics.py`  
  Работает с `identity_schema_v2.yaml`:  
  - формирует единообразные identity-объекты для моделей и запусков;  
  - обеспечивает воспроизводимость через явные идентификаторы.

- `core.py`  
  Использует логи и `output_taxonomy.yaml`:  
  - агрегирует результаты бенчмарков;  
  - строит отчёты (Markdown/HTML/CSV) для анализа.

## Как запустить

1. Подготовьте окружение:
   ```bash
   pip install -r requirements.txt
   ```
   или активируйте уже настроенную среду (conda/venv).

2. Сгенерируйте/обновите вспомогательные структуры:
   ```bash
   python generate_inputs.py
   python generate_features.py
   python generate_identities.py
   # генерация отчётов после получения результатов:
   python generate_reports.py
   ```

3. Запустите протокол экспериментов:
   ```bash
   python run_protocol.py
   ```

4. Либо запустите основной раннер напрямую:
   ```bash
   python benchmark-runner_v4_2.py
   ```

## Принципы дизайна

- В корне репозитория только актуальные версии скриптов и конфигов (устаревшие раннеры и временные MD-доки удалены).  
- Воспроизводимость экспериментов обеспечивается через `experiment_protocol.yaml` и `identity_schema_v2.yaml`.  
- Конфиги и код разделены:
  - запуск и управление (`benchmark-runner_v4_2.py`, `run_protocol.py`);
  - описания данных и метрик (YAML-файлы);
  - генерация вспомогательных структур и отчётов (четыре генератора).
