# D2 Blues: два типа постера, параметры, источники, границы (v8.2)

Статус: контракт перед реализацией BluesCompositionGrammarV8.

## 0. Цель и правила

Цель: генератор визуальной личности блюза, где вся геометрия причинно выводится по цепочке Audio → E1 → E2 θ → BluesBridgeParams → SVG и записывается в MappingTrace.

Правила:
- Один трек → одна картина. Альтернативных картинок не плодим.
- Тип постера выбирается один раз на трек и внутри трека не переключается.
- Вариативность идёт только внутри числовых коридоров разделов 4–8.
- Любой параметр без измеренного источника помечается `derived_estimate`.

## 1. Формат холста (полароид)

| Область | Размер | Координаты |
|---|---|---|
| Сцена | 1080×1080 | x 0…1080, y 0…1080 |
| Плашка паспорта | 1080×180 | y 1080…1260 |
| Итоговый файл | 1080×1260 | |

Правила края: все элементы сцены обрезаются по прямоугольнику сцены с внутренним полем 24 px. Ничто не должно вылезать за края постера и заходить на плашку. Радиусы, тени и шлейфы считаются с запасом, а не «впритык».

## 2. Два типа постера

| Тип | `blues_poster_type` | Смысл | Сцена |
|---|---|---|---|
| S | `solitude` | Одиночество: одно тело оседает к земле | Тело-чаша, тень на поверхности, roots/rails, нижний узел, спектральные круги, funnel. Нет второго тела, моста, inter-body field |
| D | `dialogue` | Взаимодействие двух тел: Голос и Тело | Голос (цветок-воронка), Тело (резонаторная чаша), мост call-and-response, contact_seam, inter-body field |

### Выбор типа (аналог dominant_mode в роке)

В роке `dominant_mode` («structure» или «organic») выбирает гнездо или бутон по θ1 против θ7. Для блюза тип выбирается по мягкому счёту:

\[ dialogue\_score = 0.30\,\theta_4 + 0.25\,\theta_2 + 0.20\,repetition + 0.15\,onset\_rate\_norm + 0.10\,G \]

| Условие | Тип |
|---|---|
| dialogue_score ≥ 0.55 | `dialogue` |
| dialogue_score ≤ 0.45 | `solitude` |
| между 0.45 и 0.55 | `solitude` (нейтральный) |

Пороги и веса предварительные. Они калибруются на корпусе из раздела 11 до заморозки.

Смысл: плотные, контрастные по частям, повторяющиеся треки с частыми атаками (перекличка голоса и инструмента) дают диалог. Разреженные, ровные, медленные треки с одним несущим голосом дают одиночество.

## 3. Таблица управления (аналог таблицы рока)

| Визуальный элемент | Управляющий параметр | Музыкальный источник | Физико-музыкальный смысл |
|---|---|---|---|

| Слайдовая деформация лент | `Abend = 8 + 28·θ3` | θ3 (напряжение) | Блюзовая нота и бенд изгибают ленты |

| Число лент в чаше | 3…7 по G | G | Плотность и повторяемость грува |
| Число лепестков Голоса (D) | N = 3 / 5 / 7 по V | V | Присутствие вокала или соло |
| Неравномерность лепестков | `εk = 0.18·(θ3 − 0.5)·sin(3k + θ6)` | θ3, θ6 | Напряжение ломает симметрию |
| Длина лепестков | `Lk = L0·[1 + 0.22·V·sin φk + 0.18·E·cos(2φk + θ3)]` | V, E, θ3 | Яркость голоса и электрический жар |
| Изгиб моста (D) | `As = 25 + 70·θ3` | θ3 | Амплитуда blue note в перекличке |
| Сдвиг ответа (D) | `δswing = 0.12π + 0.18π·repetition·(1 − stability)` | repetition, stability | Шаффл и запаздывание ответа |
| Толщина моста | растёт с E | E | Электрический жар |
| Хвост моста | растёт при низком BPM | BPM | Тянущееся эхо |
| Электрический край | синий, α = (E − 0.6)/0.4 при E > 0.6 | E | Электричество усилителя на краях форм |
| Искры и графитовая пыль | плотность по E | E, noise_proxy | Шум, ламповый гул |
| Индивидуальный seed | `seed_sha256` | `sha256(canonical_theta_hash + feature_sha256)` | Воспроизводимость |

## 4. Производные оси

Все входы нормируются в [0, 1] и ограничиваются clamp. BPM в формулах ограничен диапазоном 55…145.

| Ось | Формула | Диапазон |
|---|---|---|
| tempoNorm | clamp((BPM − 55) / 90, 0, 1) | [0, 1] |
| G groove_weight | 0.30·density + 0.25·repetition + 0.20·energy + 0.15·stability + 0.10·tempoNorm | [0, 1] |
| V vocal_presence | 0.30·brightness + 0.25·θ0 + 0.20·smoothness + 0.15·stability + 0.10·(1 − noise_proxy) | [0, 1] |
| E electric_heat | 0.30·drive + 0.25·noise_proxy + 0.20·θ3 + 0.15·θ5 + 0.10·θ4 | [0, 1] |

Признаки swing_ratio, vocal_presence, low_end_ratio, bend_vibrato_rate в E1 пока не измеряются. До их появления значения берутся из формул выше и помечаются `derived_estimate`.

## 5. Положение тел (сцена 1080×1080)

### Тип D

| Параметр | Формула | Границы при G, V, E ∈ [0, 1] |
|---|---|---|
| xA (Голос) | 540 − 120·G + 55·V | 420 … 595 |
| yA | 360 − 70·V − 35·E | 255 … 360 |
| xB (Тело) | 540 + 120·G − 45·V | 495 … 660 |
| yB | 680 + 110·G + 45·E | 680 … 835 |

Инварианты:
- yB − yA ≥ 320 px (минимум при G = V = E = 0), иначе диалога нет.
- yB + радиус чаши ≤ 1080 − 24. Запас под чашу снизу до границы сцены: от 221 px при yB = 835.
- Голос выше и левее центра масс, Тело ниже и правее.
- Все элементы укладываются в сцену с полем 24 px.

### Тип S

- Одно тело: x = 540, y = yB по формуле выше (подтверждено автором).
- Голоса, моста и inter-body field нет.
- Верх кадра отдан пустоте и тени, это часть смысла.

## 6. Тело: резонаторная чаша (оба типа)

- Катеноид: y(x) = y0 + a·[cosh((x − x0)/a) − 1], практический диапазон a ≈ 110 … 268.
- Слайдовая деформация: y'(x) = y(x) + Abend·sin(2πx/λbend + ψ), Abend = 8 … 36 px, λbend = 100 … 280 px.
- Лент в чаше от 3 до 7. Roots слегка ослаблены, нижний узел усилен локально.
- Тип S добавляет тень на поверхности и спектральные круги нижнего плана. Тип D ослабляет их, чтобы не конкурировать с мостом.
- Радиус и размах чаши подбираются крупно, без мелочи, и обязательно проверяются на соблюдение поля 24 px по всем границам сцены.

## 7. Голос и мост (только тип D)

Голос:
- N лепестков: 3 при V < 0.35; 5 при 0.35 ≤ V < 0.65; 7 при V ≥ 0.65.
- Максимальное смещение углов |ε| ≈ 0.09 рад. Длина лепестка в коридоре 0.6·L0 … 1.4·L0. Opacity 0.35 … 0.65.
- 12-лепестковая симметрия запрещена.

Мост B(t) — кубическая кривая Безье от PA к PB, где PA и PB берутся из `seam_pts`:
- C1 = PA + 0.33·(PB − PA) + As·(sin ψ, cos ψ)
- C2 = PA + 0.66·(PB − PA) − As·(sin(ψ + δswing), cos(ψ + δswing))
- As = 25 … 95 px, δswing = 0.12π … 0.30π.

Роли:
- Мост и inter-body field строятся только от `seam_pts` и притяжения/отталкивания. Тела не рисуют собственных полей.
- Прямая линия Голос–Тело запрещена.
- `_counterflow` удаляется из кода целиком (определение, вызовы, параметры). Проверка: поиск по `_counterflow` в `tools/render_d2_blues_poster.py` возвращает пустой результат.

## 8. Стилистические режимы внутри типа

Режим сдвигает параметры только внутри коридоров разделов 5–7. Выбор: argmax мягкого счёта; при разнице со вторым местом меньше 0.05 берётся нейтральный режим.

| Режим | Признаки | Допустим в типе | Эффект |
|---|---|---|---|
| slow_delta | BPM низкий, smoothness высокий, drive низкий | S, D | Очень глубокая чаша, тонкий длинный мост |
| vocal_soul | V, brightness, stability высокие | D | Яркая воронка с нимбом, мягкий резонатор |
| shuffle | repetition и onset_rate высокие, средний BPM | D | Компактная розетка, серия коротких смещённых линий |
| electric_chicago | E, grain, density высокие | S, D | Плотное низкое тело, толстый мост, искры, дым |
| guitar_texas | атака и section_complexity высокие | D | Острые лепестки-слайды, прерывистые траектории |

## 9. Палитра warm_midnight

Источник: `configs/palettes.yaml`, семейство `warm_dark`.

| Роль | Значение |
|---|---|
| Фон (RGBA) | 14, 9, 5, 255 |
| Градиент 0.00 | #0E0905 |
| Градиент 0.35 | #3D2210 |
| Градиент 0.68 | #8B4F1A |
| Градиент 1.00 | #D4923A |
| Акцент | #F5C97A |
| Электрический край (новый) | #3F8FD2 |
| saturation_budget | 0.62 |
| contrast | 1.12 |
| luminance_gamma | 0.96 |

Принципы:
- Один тёплый акцент на план. Электрический край не считается вторым акцентом, это отдельная роль `electric_edge`: тонкая кромка форм, которая появляется только при E > 0.6 и усиливается линейно до E = 1.
- Голос берёт цвета из верха градиента, Тело из низа.
- Синий не заливает формы и не используется как фон.
- Изменение реестра палитр (`electric_edge` в `warm_midnight`) требует правки валидатора палитр, иначе неизвестное поле будет отклонено. Статус: решение принято, правка реестра ещё не внесена.

## 10. Паспорт и воспроизводимость

- Seed = sha256(canonical_theta_hash + feature_sha256), внешней случайности нет.
- В MappingTrace для каждого параметра: имя, формула, входы, источник (`measured` или `derived_estimate`), итоговое значение, применённый clamp.
- Плашка 1080×180 внизу, цвет #14100E, название прописными, hash моноширинным шрифтом.

## 12. Критерии готовности

1. Все параметры из разделов 2–7 имеют записи в MappingTrace.
2. `_counterflow` отсутствует в коде.
3. Тип постера выбирается один раз на трек и записан в трейс.
4. Для эталонных треков каждого типа и режима различия видны глазами.
5. Один и тот же трек даёт побитово идентичный SVG.
6. Инварианты раздела 5 выполняются на всём корпусе, за края сцены 1080×1080 и поле 24 px ничего не выходит.
7. Итоговый файл 1080×1260, плашка 180 не перекрывается сценой.
