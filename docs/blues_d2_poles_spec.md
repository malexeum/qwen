# Two Poles of Blues Visual Grammar

## Назначение

Этот документ фиксирует два полюса визуальной грамматики Blues в AVCoder: полюс одиночного оседания и полюс двухтелого удерживаемого разрыва. Второй полюс реализуется через `tools/render_d2_blues_poster.py` и уже закреплён как отдельный renderer для `Two-Body Blues`.[cite:349]

Цель документа — не придумать новую архитектуру, а зафиксировать инвентаризацию сущностей, допустимые границы параметров и критерии различимости полюсов, чтобы следующие правки не размывали замысел и не смешивали режимы между собой.[cite:349]

# D2 Blues: два полюса, параметры, источники, границы (v8-spec)

Статус: черновик-контракт перед реализацией BluesCompositionGrammarV8.
Правило: один трек → одна картина. Новых «альтернативных картинок» не плодим.
Вариативность идёт только через `blues_mode` внутри ограниченных коридоров.

## 0. Цель (одним предложением)
Генератор визуальной личности блюза: система двух притяжений (Голос ⟷ Тело)
с запаздывающим откликом между ними; все параметры причинно выводятся из
Audio → E1 → E2 θ → BluesBridgeParams → SVG и записываются в MappingTrace.

## 1. Онтология сцены (инвентаризация)

| Слой | Сущность | Музыкальная функция | Статус |
|---|---|---|---|
| Полюс A | Цветок-воронка (3/5/7 неравных лепестков), нимб, мембраны | Вокал, соло, «вопрос» | обязателен |
| Полюс B | Резонаторная чаша: вложенные провисающие ленты (катеноид) + дымный низ + roots | Бас, грув, «ответ» | обязателен |
| Мост | Лента call-and-response (кубический Безье), contact_seam, inter-body field | Задержка, bend, blue note | обязателен |
| Среда | Фон warm_midnight, зерно бумаги, пыль графита, редкие искры | Воздух, шум, электричество | опционален (по E) |
| Паспорт | Нижняя плашка 1080×180, title + identity hash | Provenance | обязателен |
| Запрещено | `_counterflow` (признан ложноположительным шумом), 12-лепестковая симметрия, прямая линия A–B | | удалить из активного кадра |

## 2. Производные оси (источник → формула → границы)

Все входы нормируются в [0, 1] и ограничиваются clamp.

| Ось | Формула | Диапазон |
|---|---|---|
| tempoNorm | clamp((BPM − 55) / 90, 0, 1) | [0, 1] |
| G groove_weight | 0.30·density + 0.25·repetition + 0.20·energy + 0.15·stability + 0.10·tempoNorm | [0, 1] |
| V vocal_presence | 0.30·brightness + 0.25·θ0 + 0.20·smoothness + 0.15·stability + 0.10·(1 − noise_proxy) | [0, 1] |
| E electric_heat | 0.30·drive + 0.25·noise_proxy + 0.20·θ3 + 0.15·θ5 + 0.10·θ4 | [0, 1] |

Честность данных: эти оси пока производные оценки. Четыре будущие фичи
(swing_ratio, vocal_presence, low_end_ratio, bend_vibrato_rate) в E1 не
измеряются. Fallback помечается в MappingTrace как `derived_estimate`.

## 3. Полюса: положение (холст 1080 по X)

| Параметр | Формула | Границы при G,V,E ∈ [0,1] |
|---|---|---|
| xA | 540 − 120·G + 55·V | 420 … 595 |
| yA | 360 − 70·V − 35·E | 255 … 360 |
| xB | 540 + 120·G − 45·V | 495 … 660 |
| yB | 680 + 110·G + 45·E | 680 … 835 |

Инварианты:
- Расстояние |PA−PB| по вертикали ≥ 320 px (иначе нет диалога, система схлопывается).
- yB + радиус чаши ≤ верхний край плашки паспорта (проверить: см. вопрос 3).
- A всегда выше и левее центра масс, B ниже и правее (направленная асимметрия).

## 4. Полюс A: цветок-воронка

- Число лепестков N: 3 при V < 0.35; 5 при 0.35 ≤ V < 0.65; 7 при V ≥ 0.65 (предложение).
- Углы: φk = 2πk/N + εk, εk = 0.18·(θ3 − 0.5)·sin(3k + θ6). Макс. |ε| ≈ 0.09 рад.
- Длина: Lk = L0·[1 + 0.22·V·sin φk + 0.18·E·cos(2φk + θ3)]. Коридор: 0.6·L0 … 1.4·L0.
- Opacity лепестков 0.35–0.65. Нимб: радиус растёт с V, резкость края падает с E.

## 5. Полюс B: резонаторная чаша

- Катеноид: y(x) = y0 + a·[cosh((x − x0)/a) − 1].
- Провисание: a = 150·(1 + 0.7·G)·(1 − 0.35·(BPM − 70)/100). Практический диапазон a ≈ 110 … 268.
- Слайдовая деформация: y'(x) = y(x) + Abend·sin(2πx/λbend + ψ).
  - Abend = 8 + 28·θ3 (8 … 36 px).
  - λbend = 100 + 180·(1 − drive) (100 … 280 px).
- Лент в чаше: 3 … 7 (по G); roots слегка ослаблены, нижний узел усилен локально.

## 6. Мост: call-and-response

B(t) — кубический Безье от PA к PB.
- C1 = PA + 0.33·(PB − PA) + As·(sin ψ, cos ψ)
- C2 = PA + 0.66·(PB − PA) − As·(sin(ψ + δswing), cos(ψ + δswing))
- As = 25 + 70·θ3 (25 … 95 px)
- δswing = 0.12π + 0.18π·repetition·(1 − stability) (0.12π … 0.30π)
- Толщина ленты растёт с E; хвост ленты растёт при низком BPM.
- Inter-body field строится только от seam_pts и притяжения/отталкивания.

## 7. Режимы (blues_mode)

Выбор: мягкий score по каждому режиму, победитель = argmax. Ничья → режим
с большим |score − 2-й|; при разнице < 0.05 режим `vocal` (нейтральный).
Режим сдвигает параметры только внутри коридоров разделов 3–6.

| Режим | Основные признаки | A | B | Мост |
|---|---|---|---|---|
| slow_delta | BPM низкий, smoothness↑, drive↓ | малый, тлеющий | очень глубокая | длинная, тонкая |
| vocal_soul | V↑, brightness↑, stability↑ | яркая воронка + нимб | мягкий резонатор | несколько эхо-мембран |
| shuffle | repetition↑, onset_rate↑, средний BPM | компактная пружинная розетка | ритмичные дуги | серия коротких смещённых линий |
| electric_chicago | E↑, grain↑, density↑ | медно-янтарное ядро, синий край | низкое плотное гнездо | толстая, искры, дым |
| guitar_texas | атака↑, section_complexity↑ | острые лепестки-слайды | лёгкая чаша | длинные прерывистые траектории |

Пороги score: калибруются на корпусе, пока не зафиксированы (см. вопрос 4).

## 8. Паспорт и воспроизводимость

- seed = sha256(canonical_theta_hash + feature_sha256); без внешней случайности.
- В MappingTrace для каждого параметра: имя, формула, входы, источник
  (`measured` | `derived_estimate`), итоговое значение, применённый clamp.
- Плашка 1080×180, цвет #14100E, title верхним регистром, hash моноширинным.

## 9. Палитра

Палитра warm_midnight фиксируется отдельным блоком (hex-значения) после
подтверждения автором. Принцип: тёмный нейтральный фон, один тёплый акцент (A),
один глубокий низ (B), синий только как электрический край при E > 0.6.

## 10. Критерии готовности (до начала реализации)

1. Все параметры из §2–6 имеют записи в MappingTrace.
2. `_counterflow` отсутствует в вызовах.
3. Для 5 эталонных треков (по одному на режим) режимы различимы глазами.
4. Один и тот же трек даёт побитово идентичный SVG.
5. Инварианты §3 выполняются на всём корпусе.
